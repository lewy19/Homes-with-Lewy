Send Make scenario analytics to the dashboard

Each event appears in Analytics as a success, failure or skip. Send only aggregate labels; never send names, phone numbers, email addresses or enquiry messages.

One-time setup

  1. Run supabase/add-make-analytics.sql in the Supabase SQL Editor after the lead analytics migration.
  2. Create a random secret of at least 32 characters. Store it in Supabase as MAKE_ANALYTICS_WEBHOOK_SECRET and in Make's secret storage. Never add it to a browser setting.
  3. Deploy the make-analytics Edge Function. It uses the standard SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY function secrets.
  4. In Supabase CLI, run supabase secrets set MAKE_ANALYTICS_WEBHOOK_SECRET=..., then supabase functions deploy make-analytics.
  5. In Make, add an HTTP → Make a request module. Use POST to https://PROJECT_REF.supabase.co/functions/v1/make-analytics.
  6. Add headers x-make-analytics-secret: YOUR_SECRET, apikey: YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY and Content-Type: application/json; send a raw JSON body. The publishable/anon key may be used in Make; never use the service role key.

Example body

{
  "event_name": "automation_succeeded",
  "page_path": "/integrations/make",
  "project_slug": "manna-residence",
  "source": "make",
  "campaign": "lead-follow-up",
  "device": "desktop"
}

Accepted automation event names are automation_succeeded, automation_failed and automation_skipped. A Make error handler can send failures; add only one reporting module per outcome because retries are counted as new events. You can also send an existing website analytics event name. The optional project slug and campaign label appear in the dashboard breakdowns.
